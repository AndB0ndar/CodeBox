# ВВЕДЕНИЕ

Наименование программы: **"CodeBox"**.

Программа представляет собой веб-приложение для безопасного удалённого выполнения пользовательского кода в изолированных Docker-контейнерах.  
Область применения: образовательные платформы для проверки заданий по программированию, системы непрерывной интеграции (CI/CD), платформы для тестирования кода в изолированной среде, а также любые сценарии, требующие безопасного запуска произвольного кода с возможностью сбора метрик и логов.

Объект применения: вычислительные комплексы и рабочие станции разработчиков, систем интеграции, а также серверные инфраструктуры организаций, использующих контейнерную изоляцию.

# ОСНОВАНИЯ ДЛЯ РАЗРАБОТКИ

Условное обозначение темы: "CodeBox".

# НАЗНАЧЕНИЕ РАЗРАБОТКИ

Функциональное назначение: обеспечение веб-интерфейса и REST API для отправки пользовательского кода (на языках Python, JavaScript, Bash), управления задачами их выполнения в изолированных Docker-контейнерах, отслеживания хода выполнения в реальном времени, сбора логов и метрик использования ресурсов (CPU, память).

Эксплуатационное назначение: программа предназначена для использования разработчиками, преподавателями, исследователями и интеграторами в процессах обучения программированию, автоматизированного тестирования кода, безопасного выполнения скриптов и анализа производительности.

# ТРЕБОВАНИЯ К ПРОГРАММНОМУ ИЗДЕЛИЮ

## Требования к функциональным характеристикам

Программа должна обеспечивать выполнение следующих функций.

**Аутентификация и управление доступом:**

- Аутентификация пользователей по паре "имя пользователя/пароль" с выдачей JWT-токена.
- Защита от несанкционированного доступа к задачам (пользователь имеет доступ только к своим задачам).
- Поддержка ролей: обычный пользователь, администратор (возможность просмотра всех задач).
- Механизм ограничения количества одновременных задач на пользователя (квотирование).

**Управление задачами выполнения кода:**

- Приём кода на языках: Python, JavaScript (Node.js), Bash (с возможностью расширения списка).
- Приём параметров выполнения: ограничение по CPU (доли ядер), памяти (строка, например "256m"), таймауту (секунды).
- Постановка задачи в очередь (Redis) с возвратом идентификатора задачи.
- Выполнение кода в Docker-контейнере с применением ограничений ресурсов (CPU, память, число процессов, файлов), изолированной файловой системы (read-only, tmpfs), отключёнными сетевыми возможностями (по умолчанию).
- Сбор stdout/stderr контейнера и сохранение в объектном хранилище (MinIO) с возможностью потоковой загрузки.
- Сбор метрик использования CPU и памяти в реальном времени (раз в секунду) с вычислением максимальных и средних значений.
- Отслеживание статуса выполнения (queued, running, completed, failed, timeout).
- Возможность отмены выполняемой задачи.
- Уведомление клиентов об изменении статуса через Server‑Sent Events (SSE) на базе Redis Pub/Sub.

**Пользовательский интерфейс:**

- Веб-интерфейс на русском языке (с возможностью локализации).
- Форма отправки кода с выбором языка и настройкой ограничений (CPU, память, таймаут).
- Страница детального просмотра задачи с отображением статуса, кода, логов (вкладка) и метрик (вкладка с графиком).
- Список задач пользователя с фильтрацией по статусу и пагинацией.
- Адаптивный дизайн с использованием Bootstrap 5, подсветка синтаксиса кода (CodeMirror), визуализация метрик (Chart.js).

**API для интеграции (REST):**

- Регистрация и аутентификация (JWT).
- Создание задачи, получение статуса, логов (presigned URL), метрик, списка задач.
- Потоковое получение обновлений статуса через SSE.

## Требования к надежности

**Обеспечение устойчивого функционирования:**

- Время непрерывной работы без сбоев: не менее 3 месяцев.
- Автоматическое восстановление воркеров после сбоев (задачи не теряются, перезапускаются).
- Контроль целостности данных при передаче кода и результатов.
- Валидация входных данных (размер кода, корректность параметров) перед постановкой в очередь.

**Восстановление после сбоев:**

- Время восстановления после программного сбоя: не более 5 минут (перезапуск контейнеров сервисов).
- Автоматическое сохранение состояния задач в базе данных MongoDB.
- Резервное копирование конфигурационных данных и логов (MinIO, MongoDB).
- Возможность перезапуска отложенных задач при восстановлении воркера.

**Обработка ошибок:**

- Детальное логирование всех операций (уровни DEBUG, INFO, ERROR) с централизованным сбором (Loki).
- Защита от некорректных входных данных на уровне API и веб-форм.
- Гибкая система обработки исключительных ситуаций с возвратом понятных клиенту сообщений.

## Требования к составу и параметрам технических средств

**Минимальная конфигурация:**

- Процессор: x86-64 архитектура, 2 ядра, тактовая частота от 2 ГГц.
- Оперативная память: 4 ГБ.
- Дисковое пространство: 20 ГБ (с учётом хранения логов и образов Docker).
- Сетевой адаптер: Ethernet 100/1000 Мбит/с.
- Устройства ввода-вывода: клавиатура, монитор (разрешение не менее 1280×720).

**Рекомендуемая конфигурация:**

- Процессор: 4+ ядер, тактовая частота от 3 ГГц.
- Оперативная память: 8 ГБ и более.
- Дисковое пространство: 100 ГБ (SSD) для хранения логов и метрик.
- Сетевой адаптер: Gigabit Ethernet.
- Резервное питание: ИБП.

**Дополнительное ПО:**

- Docker Engine 20.10+.
- Docker Compose (для локального развёртывания) или Kubernetes (для production).
- Доступ к MongoDB, Redis, MinIO (могут быть развёрнуты в контейнерах).

## Требования к информационной и программной совместимости

**Информационная совместимость:**

- Входные форматы: текст кода (UTF-8) на поддерживаемых языках (Python, JavaScript, Bash) и параметры выполнения в JSON.
- Выходные форматы: текстовые логи (plain text), JSON с метриками, архивы (при необходимости).
- Кодирование данных: UTF-8.

**Программная совместимость:**

- Операционные системы: Linux (Ubuntu 20.04+, Debian 11+, CentOS 8+), Windows 10/11 (с WSL2 и Docker Desktop), macOS 11+ (с Docker Desktop).
- Веб-браузеры: Chrome 90+, Firefox 88+, Safari 14+, Edge 90+.
- Базы данных: MongoDB 6+.
- Очереди и кэши: Redis 7+.
- Объектное хранилище: MinIO 2023+.
- Язык реализации: Python 3.10+.
- Веб-фреймворки: FastAPI (backend), Flask (web).
- Контейнеризация: Docker.

**Внешние интерфейсы:**

- REST API для взаимодействия между web-сервером и backend, а также для интеграции с внешними системами.
- Redis Pub/Sub для передачи уведомлений между воркером и backend.
- Docker API для управления контейнерами.

**Защита информации:**

- Аутентификация на основе JWT-токенов с ограниченным сроком действия (30 минут).
- Хранение паролей в хешированном виде (bcrypt).
- Контроль доступа к задачам (владелец задачи).
- Шифрование передаваемых данных (HTTPS) в production.
- Защита от SQL-инъекций (MongoDB драйвер) и XSS атак (экранирование вывода).

## Специальные требования

**Производительность:**

- Время отклика веб-интерфейса: не более 2 секунд (95-й перцентиль).
- Время обработки API-запросов: не более 500 мс для операций чтения, не более 1 с для создания задачи.
- Поддержка одновременной работы 50+ пользователей (с учётом квот на количество задач).
- Максимальное количество задач в очереди: не менее 1000.

**Безопасность выполнения кода:**

- Изоляция контейнеров: read-only rootfs, отключение привилегий (cap_drop=ALL), запрет новых привилегий (no-new-privileges), отключение сети (по умолчанию), ограничение числа процессов и файлов.
- Ограничение ресурсов (CPU, память, таймаут) на уровне Docker.
- Автоматическое удаление контейнеров после выполнения (даже при ошибках).
- Возможность полного отключения сети для задач, не требующих внешних соединений.
- Регулярное обновление базовых образов Docker.

**Масштабируемость:**

- Возможность горизонтального масштабирования воркеров (запуск нескольких экземпляров).
- Возможность запуска нескольких экземпляров backend с балансировкой нагрузки.
- Использование Redis как централизованной очереди и брокера уведомлений.

1. **Техническое проектирование** (1 месяц)
   - Анализ требований и разработка ТЗ.
   - Проектирование архитектуры системы (микросервисы: backend, worker, web).
   - Выбор технологического стека (FastAPI, Flask, MongoDB, Redis, MinIO, Docker).

   - Разработка backend на FastAPI: модели данных, API-эндпоинты, аутентификация JWT, интеграция с очередью и MongoDB.

   - Настройка Redis и MinIO.
3. **Реализация** (1.5 месяца)
   - Написание кода всех компонентов.

   - Развёртывание в опытной эксплуатации (Docker Compose / Kubernetes).
